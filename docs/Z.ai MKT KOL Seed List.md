# Z\.ai MKT KOL Seed List

## 使用原则



这份名单是 MKT Intelligence Brief 的初始 seed list，不是固定白名单。日报不应该因为某个人在名单里就自动选入；必须看当天内容是否和 Z\.ai 的产品、开发者生态、企业 GTM、startup GTM 或竞品情报有关。



优先级定义：



- `Tier A`：战略 KOL。默认进入每日监控。

- `Tier B`：新兴或垂直 KOL。有强相关内容时进入简报。

- `Tier C`：观察池。不占日报位置，除非当天内容有明确价值。

    

状态定义：



- `active`：可以进入每日筛选。

- `monitoring`：继续观察，不固定出现。

- `deprioritize`：降低权重。

- `replace_candidate`：建议找替代对象。

## 每日筛选规则



一条 KOL 内容进入日报，需要满足至少一条：



1. 直接涉及 Z\.ai 相关主题：GLM、开源模型、API、inference、model serving、coding agents、agents。

2. 涉及竞品动向：OpenAI、Anthropic、Google、Meta、xAI、Mistral、DeepSeek、Kimi、MiniMax、Qwen。

3. 对开发者生态有信息增量：新工具、新工作流、新 benchmark、新开源项目。

4. 对 startup GTM 有信息增量：新融资、新增长、新产品定位、新模型切换。

5. 对 enterprise GTM 有信息增量：企业采用、私有部署、安全、治理、成本、数据权限。

    

不进入日报的情况：



1. 只有情绪或段子，没有事实增量。

2. 与 AI 无关的个人动态。

3. 只重复已有观点。

4. 来源链接不可核验。

5. 与 Z\.ai 没有清晰关联。

    

## 维护方式



技术侧维护机器读配置：



```Plain Text
config/mkt-kols.json
```



MKT 侧维护 review 决策：



```Plain Text
active
monitoring
deprioritize
replace_candidate
```



建议每月复盘一次：



1. 哪些 KOL 连续出现但没有带来价值。

2. 哪些新作者被 watchlist 多次推荐。

3. 哪些 category 缺人，例如 enterprise buyer、AI security、model serving。

4. 是否有组织过度集中，例如 Anthropic / OpenAI 内容占比过高。
