# follow-builders 实现原理与飞书推送说明

> 这份文档讲清楚两件事：
> 1. follow-builders 整个内容是怎么实现的（从头到尾的数据流）
> 2. 早报是怎么推送到飞书群里的（重点）

---

## 一、整体实现：三步数据流

follow-builders 把"出一份早报"拆成三步，每一步职责分明：

```
[每天自动抓数据]  →  [打包成原料 JSON]  →  [AI 写成早报并推送]
  generate-feed.js     prepare-digest.js       SKILL.md 编排 + deliver.js
  (GitHub Action)       (命令触发)              (AI remix + 交付)
```

### 第一步：抓数据（每天自动跑）

- **脚本**：`scripts/generate-feed.js`
- **触发**：`.github/workflows/generate-feed.yml`，每天 6:17 UTC 自动跑（也可手动触发）
- **抓什么**：
  - 25 个 X 用户的最近 24 小时推文（每人最多 3 条）
  - 6 个播客最新一集的转写文字
  - 2 个博客（Anthropic 工程、Claude Blog）的最新文章
- **需要的密钥**（配在 GitHub 仓库的 Secrets 里）：
  - `X_BEARER_TOKEN`——X/Twitter API 密钥
  - `POD2TXT_API_KEY`——播客转写服务密钥
- **结果**：抓完存成三个文件提交回仓库
  - `feed-x.json`（推文）
  - `feed-podcasts.json`（播客）
  - `feed-blogs.json`（博客）
- **防重复**：用 `state-feed.json` 记录已抓过的推文 ID / 视频 ID / 文章链接，下次不重复抓

### 第二步：打包原料 JSON

- **脚本**：`scripts/prepare-digest.js`
- **触发**：你敲 `/ai`，或定时任务（cron）到点触发
- **干什么**：把三样东西打包成一个 JSON，给 AI 看
  1. 第一步抓到的推文 / 播客 / 博客内容
  2. 你的个人设置（语言、推送方式，存在 `~/.follow-builders/config.json`）
  3. "怎么总结"的说明文件（`prompts/` 目录下的 5 个 prompt）
- **注意**：这个脚本从 `raw.githubusercontent.com/zarazhangrui/follow-builders/main/...` 拉上游仓库的 feed（硬编码 URL）。也就是说，默认拉的是官方仓库的数据，不是你本地的。

### 第三步：AI 写成早报并推送

- **编排**：`SKILL.md`（AI 读这个文件来跑整个流程）
- **干什么**：
  1. 跑 `prepare-digest.js` 拿到 JSON
  2. AI 按 prompt 里的规矩，把内容重写成早报（每人 2-4 句、带链接、不许编造）
  3. 推送出去

推送这一步是关键，下面单独讲。

---

## 二、早报怎么推送到飞书群（重点）

### 先澄清一个重要事实

`scripts/deliver.js` 这个推送脚本**只支持三种方式**：

| 方式 | 说明 |
|---|---|
| `telegram` | 通过 Telegram Bot API 推送 |
| `email` | 通过 Resend 邮件服务推送 |
| `stdout`（默认） | 直接打印到终端 |

**deliver.js 不支持飞书。** 飞书推送不是靠这个脚本，而是靠 **OpenClaw 的通道系统**。

### 飞书推送的真正机制

follow-builders 是个"技能（skill）"，跑在 **OpenClaw** 这个常驻 agent 平台上。OpenClaw 自带消息通道（Telegram / 飞书 / Discord / Slack / WhatsApp…）。飞书推送的流程是：

```
[OpenClaw 定时任务到点]
        ↓
[启动一个独立 session，给 agent 发一条指令]
        ↓
[agent 按 SKILL.md 跑：prepare-digest.js → AI remix 出早报文本]
        ↓
[agent 把早报文本输出]
        ↓
[OpenClaw 按 cron 里配的 --channel feishu --to <飞书群 chat_id>，把输出投递到飞书群]
```

关键点：**早报文本是 agent 输出的，OpenClaw 负责把它路由到飞书群。** 不是 deliver.js 发的。

因为走 OpenClaw 通道，所以配置里：
- `platform` = `"openclaw"`
- `delivery.method` = `"stdout"`（agent 直接输出，OpenClaw 接管投递）

### 设置飞书推送的具体步骤

#### 1. 拿到飞书群的 chat_id

飞书群的目标 ID 格式是 `oc_xxx`（群聊 chat_id）。获取方式：

```bash
openclaw pairing list feishu
```

或者看网关日志：让机器人加到飞书群、在群里 @ 它发条消息，然后从日志里读 `chat.id`。

#### 2. 创建定时任务（推送到飞书群的核心命令）

```bash
openclaw cron add \
  --name "AI Builders Digest" \
  --cron "0 8 * * *" \
  --tz "Asia/Shanghai" \
  --session isolated \
  --message "Run the follow-builders skill: execute prepare-digest.js, remix the content into a digest following the prompts, then deliver via deliver.js" \
  --announce \
  --channel feishu \
  --to "oc_xxxxxxxxxxxxxxxx" \
  --exact
```

参数解释：

| 参数 | 作用 |
|---|---|
| `--cron "0 8 * * *"` | 每天早上 8 点跑（用你的时区） |
| `--tz "Asia/Shanghai"` | 时区 |
| `--session isolated` | 每次跑用独立 session，不干扰你当前对话 |
| `--message "..."` | 给 agent 的指令：跑 prepare-digest.js、按 prompt 重写、输出 |
| `--announce` | 在通道里公告这次执行 |
| `--channel feishu` | 投递到飞书通道 |
| `--to "oc_xxx"` | 投递到这个飞书群（群的 chat_id） |
| `--exact` | 精确按时间触发 |

#### 3. 验证推送是否成功

```bash
openclaw cron list              # 看任务列表
openclaw cron run <jobId>       # 立即跑一次测试
openclaw cron runs --id <jobId> --limit 1   # 看上次跑的结果/报错
```

跑完后**确认飞书群里真的收到了早报**，才算成功。

常见报错：
- "Channel is required when multiple channels are configured" → 没指定 `--channel`，加上 `--channel feishu`
- "Delivering to X requires target" → 没指定 `--to`，加上飞书群 chat_id

### 手动触发（不等定时）

在 OpenClaw 里直接敲 `/ai`，agent 立刻跑一遍流程，早报会出现在你当前对话的飞书会话里（不是群，是你跟机器人的会话）。要发到群，得靠上面 cron 的 `--to` 指定群。

## 三、飞书推送这条路的特点和限制

1. **强依赖 OpenClaw**：没有 OpenClaw，就没有飞书通道。如果你不在 OpenClaw 上跑（比如纯 Claude Code），飞书推送做不了，只能用 Telegram / 邮件 / 终端。

2. **deliver.js 在飞书场景下不干活**：配置成 `stdout`，它只是把早报打印出来，真正投递的是 OpenClaw。所以 `deliver.js` 里那套 Telegram 分段、邮件发送的逻辑，飞书场景完全用不到。

3. **早报是 agent 现场生成的**：每次 cron 触发，agent 都要重新跑 `prepare-digest.js` + AI remix，耗时约 1-2 分钟，不是预先存好的。

4. **数据源仍是上游官方仓库**：`prepare-digest.js` 硬编码拉 `zarazhangrui/follow-builders` 的 feed。所以你飞书群里收到的早报，盯的是官方那 25 个人，不是你的 30 人 KOL 列表——除非你 fork 后改 URL。

---

## 四、当前飞书推送 vs Z.ai 需求的差距

你现在的飞书推送，输出的是 follow-builders 原版"AI Builders Digest"（25 人推文摘要）。要变成 Z.ai MKT 情报 brief，除了改内容（配置/prompt/源），**飞书推送这条链路本身基本不用动**——它只是个"把 agent 输出投到飞书群"的管道，内容变了它照推。

要动的只有两点：
1. **内容端**：让 agent 输出的不再是原版 digest，而是 7 板块的 Z.ai 情报 brief（改 prompt + 配置 + 源）
2. **可选**：如果要顺带存文件（spec 要求 `data/outputs/zai-mkt-intelligence-brief.md`），在 SKILL.md 的流程里加一步"写文件"，跟飞书推送并行
